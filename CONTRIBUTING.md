# Contributing to EPUB Purifier

Thanks for helping. The most useful contributions are new detection patterns for
real-world insertions, fewer false positives, and security hardening.

## Development setup

```bash
python -m venv .venv && source .venv/bin/activate
pip install -e ".[dev,web]"
pytest -q
ruff check src tests proof
python proof/prove.py
```

Python 3.10+ is required. The suite builds its own EPUB fixtures, so no sample
books are needed (and none are committed). `proof/prove.py` builds separate
fixtures and exercises the real CLI end to end; run it after changing detection,
cleaning or repackaging, and add a scenario when you fix a regression it missed.
Add `--epubcheck /path/to/epubcheck.jar` to judge the cleaned outputs with the
official W3C validator instead of only our own verifier.

## Ground rules

1. **Never delete content on a keyword match alone.** Branding findings must be
   justified by context, and anything ambiguous uses `Remediation.REVIEW`.
2. **Preserve the book.** Chapter text, headings, styles, illustrations and
   navigation come first; a missed promotion is better than a deleted paragraph.
3. **No network, no execution.** Detectors parse data. They never fetch, resolve
   entities, run scripts or shell out.
4. **Bound everything.** Any new loop over untrusted data needs a size or count
   limit in `config.Limits`.
5. **Report honestly.** A clean result is not a safety guarantee; keep the
   disclaimer language intact.

## Adding a detection rule

1. Choose the module:
   - branding/promotional text → `detectors/content.py`
   - active content → `detectors/security.py`
   - remote resources/tracking → `detectors/resources.py`
   - CSS → `detectors/styles.py`
   - OPF/nav metadata → `detectors/metadata.py`
2. Build a `Finding` with a stable rule id (`category.thing`), severity,
   category, confidence and remediation.
3. Return a `Mutation` that performs the edit (`remove_element`,
   `strip_attribute`, `clean_text`, `drop_entry`, `rewrite_entry`).
4. If the rule removes a whole document, set `drops_entry` so the manifest,
   spine, guide and nav are pruned.
5. Add a fixture in `tests/conftest.py` and an assertion in the relevant test
   module. Include a negative case proving legitimate content survives.

## Adding documentation

Rule tables in `README.md` are generated by hand; keep them in sync with the
code, and describe *why* a rule is safe rather than only what it matches.

## Review checklist

- [ ] `pytest -q` passes, including the hostile fixtures.
- [ ] `ruff check src tests` is clean.
- [ ] New findings have evidence and a location.
- [ ] Ambiguous cases require confirmation.
- [ ] The report wording does not imply a file is safe.
- [ ] Limits still bound every new read.
